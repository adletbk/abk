# Уведомления банка: образцы и правила разбора

## Состояние

**Образцов пока нет, поэтому готовых правил для банка в приложении нет.** Формат
уведомлений не выдумывался. Всё, что приходит от банка, сейчас попадает в раздел
«Проверить» как неразобранное, и оттуда операцию можно создать вручную.

Движок разбора, редактор правил, дедупликация и автокатегория готовы и покрыты тестами
на выдуманных текстах, нарочно не похожих ни на один банк (`tests/parser.test.js`,
`tests/inbox.test.js`).

## Как передать образцы

1. Скопируйте тексты настоящих уведомлений в файл `samples/notifications.txt`, по одному
   на абзац, с пустой строкой между ними. Папка `samples/` стоит в `.gitignore`
   и в репозиторий не попадает.
2. Нужны разные виды: покупка картой, оплата по QR, перевод другому человеку, перевод
   между своими счетами, пополнение, зачисление зарплаты, возврат, снятие наличных,
   отклонённая операция, реклама.
3. Текст нужен в точности: с пробелами, знаками и переносами. Суммы и имена можно
   заменить на похожие по виду (`4 500 ₸` → `1 234 ₸`), но не менять формат.
4. Если есть SMS от банка, добавьте и их, пометив `SMS:` в начале абзаца.

По образцам сюда будет добавлена таблица «текст → что из него получается» и набор правил,
а в тесты — проверки на каждом образце.

## Как устроено правило

Правило создаётся в приложении: Настройки → «Правила разбора» → «Новое правило».
Пересобирать приложение не нужно.

| Поле | Назначение |
|---|---|
| Название | для списка правил |
| Откуда приходит текст | уведомление банка, SMS, Apple Pay (можно несколько) |
| Что это за операция | расход, доход или перевод |
| Условие | правило применяется, только если текст подходит под это выражение. Пусто — ко всем |
| Сумма | выражение с группой в скобках; группа — это сумма. Обязательно |
| Получатель | выражение с группой; группа — название получателя. Необязательно |
| Счёт по тексту | выражение с группой, например последние цифры карты. Сравнивается с «подсказкой» и названием счетов |
| Счёт | фиксированный счёт для всех операций по этому правилу. Важнее, чем «счёт по тексту» |

Выражения — регулярные выражения JavaScript, регистр букв не учитывается. Вместо первой
группы можно использовать именованную: `(?<amount>…)`.

Как применяются правила:

- подходящие по источнику и включённые правила перебираются по порядку;
- срабатывает первое, чьё условие подошло и которое нашло сумму;
- сумма понимается в видах `4 500`, `4 500,50`, `4,500.00`, `4.500`, `4500.5`; знак
  игнорируется, расход или доход задаёт правило;
- валюта определяется по знакам `₸`, `тг`, `KZT`, `$`, `USD`, `€`, `EUR`, `₽`, `руб`;
  если знака нет, считается тенге;
- счёт: фиксированный из правила → найденный по тексту → последний использованный;
- если ни одно правило не нашло сумму, запись остаётся в «Проверить» с причиной
  «нет правила».

В редакторе правила есть поле «Проверка на примере»: вставьте текст уведомления и сразу
увидите, что из него получится. Из раздела «Проверить» правило можно создать прямо по
неразобранной записи: её текст подставится в пример.

### Пример (выдуманный текст)

Это не формат какого-либо банка, а иллюстрация полей.

Текст: `ТЕСТ: списание 4 500 ₸ в МАГАЗИН-1. Счёт *1234`

| Поле | Значение |
|---|---|
| Условие | `списание` |
| Сумма | `списание\s+([\d\s.,]+)` |
| Получатель | `в\s+(.+?)\.` |
| Счёт по тексту | `\*(\d{4})` |
| Что это за операция | Расход |

Результат: расход 4 500 ₸, получатель «МАГАЗИН-1», счёт с подсказкой `1234`.

## Получатель → категория

Когда вы открываете автоматическую операцию, выбираете категорию и сохраняете,
приложение запоминает пару «получатель → категория». Следующая операция с тем же
получателем получит категорию сама и не попадёт в «Проверить».

Получатели сравниваются без учёта регистра и знаков препинания. Сначала ищется точное
совпадение, затем вхождение одного названия в другое (от четырёх символов): запомненный
«magnum» подойдёт к «MAGNUM CASH&CARRY №12».

Список запомненных пар: Настройки → «Правила разбора» → «Получатели и категории».
Там же пару можно удалить.

## Дедупликация

Apple Pay и уведомление банка об одной покупке дают одну операцию, если совпали сумма,
валюта и тип, разница во времени не больше пяти минут и получатели не противоречат друг
другу (или один из них неизвестен). Источники объединяются: в списке операция помечена
«Apple Pay + банк».

Две одинаковые записи из одного источника не склеиваются: две одинаковые покупки подряд —
это две операции. Ручные операции с автоматическими не склеиваются никогда.

## Где хранятся правила

Только на устройстве и в JSON-бэкапе. В Google Таблицу правила не отправляются.
