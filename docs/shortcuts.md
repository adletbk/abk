# Команды iOS: автоматические траты

Команды на iPhone ловят оплату и отправляют сырой текст в вашу Google Таблицу (лист
`inbox`). Приложение при открытии забирает эти записи и превращает их в операции. Весь
разбор происходит в приложении; Команда только пересылает.

Сначала выполните [setup-google.md](setup-google.md): нужны **адрес веб-приложения** и **токен**.

> **Что здесь не проверено.** Эта инструкция написана без доступа к iPhone с iOS 27.
> Автоматизация «Транзакция» и действие «Получить содержимое URL» существуют давно, их
> шаги описаны по известному поведению. Триггер «Уведомление» описан по вашему заданию:
> его названия пунктов и доступные поля я проверить не мог. Если на телефоне что-то
> называется иначе или поля нет, пришлите снимок экрана, и я исправлю инструкцию.

## Общая часть: действие отправки

Все три Команды заканчиваются одним действием **«Получить содержимое URL»**:

| Поле | Значение |
|---|---|
| URL | адрес веб-приложения, `https://script.google.com/macros/s/…/exec` |
| Метод | `POST` |
| Тело запроса | `JSON` |

Поля JSON (кнопка «Добавить новое поле», тип «Текст», если не сказано иное):

| Ключ | Значение |
|---|---|
| `token` | ваш токен |
| `action` | `add` |
| `source` | `applepay`, `notification` или `sms` |
| `text` | сырой текст (см. каждую Команду) |
| `time` | время события в формате ISO 8601 |

`time` получите действием **«Форматировать дату»**: дата «Текущая дата», формат даты
«ISO 8601», переключатель «Включить время ISO 8601» включён. Получится
`2026-11-13T14:10:00+05:00`. Поле нужно не только для даты операции: по нему скрипт узнаёт
повторную отправку той же записи и не создаёт дубль.

Токен хранится внутри Команды. Не делитесь этими Командами и их снимками экрана.

## А. Apple Pay

Срабатывает при оплате телефоном или часами у терминала. Оплата в интернете, переводы
и QR сюда не попадают; изредка событие не приходит совсем. Поэтому Команда Б дополняет её,
а приложение склеивает обе записи об одной покупке в одну операцию.

1. Приложение **«Команды»** → вкладка **«Автоматизация»** → **«+»**.
2. Выберите **«Транзакция»** (значок Wallet).
3. Отметьте карты, по которым нужно ловить оплату. Категории оставьте все.
4. Внизу выберите **«Запускать немедленно»** и выключите «Уведомлять при запуске» → «Далее».
5. **«Новая пустая автоматизация»**.
6. Добавьте действие **«Форматировать дату»** (как описано выше).
7. Добавьте действие **«Получить содержимое URL»** и заполните общую часть:
   - `source`: `applepay`
   - `text`: переменная **«Входные данные быстрой команды»** → свойство **«Продавец»**
   - `time`: результат «Форматировать дату»
   - добавьте поле типа **«Словарь»** с ключом `payload` и тремя текстовыми значениями внутри:

     | Ключ | Значение |
     |---|---|
     | `amount` | «Входные данные быстрой команды» → **«Сумма»** |
     | `merchant` | «Входные данные быстрой команды» → **«Продавец»** |
     | `card` | «Входные данные быстрой команды» → **«Карта или пропуск»** |

8. «Готово».

Записи Apple Pay приложение разбирает без правил: сумма, продавец и карта приходят
отдельными полями. Чтобы операция попадала на нужный счёт, в приложении откройте
Настройки → Счета → счёт → «Подсказка для автоматических трат» и впишите фрагмент
названия карты из Wallet (например, последние цифры). Без подсказки берётся последний
использованный счёт.

## Б. Уведомления банка

Ловит то, чего не видит Apple Pay: оплату в приложении банка, QR, переводы, пополнения.

1. «Команды» → «Автоматизация» → «+».
2. Выберите триггер **«Уведомление»**.
3. Приложение: **приложение вашего банка**. Не выбирайте приложения QR-сервисов и
   маркетплейсов: их уведомления не про движение денег.
4. Если есть фильтр по тексту, оставьте его пустым: отбором занимается приложение.
5. **«Запускать немедленно»**, «Уведомлять при запуске» выключить → «Далее».
6. «Новая пустая автоматизация».
7. «Форматировать дату».
8. «Получить содержимое URL», общая часть и:
   - `source`: `notification`
   - `text`: входные данные автоматизации → **текст уведомления (Body, «Содержимое»)**.
     Заголовок уведомления не нужен.
   - `time`: результат «Форматировать дату»
   - `payload` не добавляйте.
9. «Готово».

Рекламные и служебные уведомления банка тоже будут приходить. Это нормально: в приложении
они окажутся в разделе «Проверить», где их можно пометить «Это не операция».

## В. SMS (запасной вариант)

Нужен, если банк шлёт SMS, а уведомления приложения отключены или триггер «Уведомление»
на вашем телефоне недоступен. Если работает Команда Б, эту не включайте: одна покупка
придёт дважды из двух «банковских» источников.

1. «Команды» → «Автоматизация» → «+» → **«Сообщение»**.
2. «Отправитель»: имя или номер, с которого пишет банк. Если отправителя выбрать нельзя,
   заполните «Сообщение содержит» словом, которое есть в каждом SMS банка.
3. «Запускать немедленно» → «Далее» → «Новая пустая автоматизация».
4. «Форматировать дату».
5. «Получить содержимое URL», общая часть и:
   - `source`: `sms`
   - `text`: «Входные данные быстрой команды» → **«Содержимое»** (текст сообщения)
   - `time`: результат «Форматировать дату»
6. «Готово».

## Проверка

1. Создайте обычную Команду (не автоматизацию) из двух действий: «Форматировать дату» и
   «Получить содержимое URL» с `source` = `sms` и `text` = `проверка связи`. Запустите её.
2. Действие вернёт ответ скрипта. Должно быть `{"ok":true,"id":"…","duplicate":false}`.
3. В таблице на листе `inbox` появится строка со статусом `new`.
4. Откройте приложение и нажмите кнопку синхронизации. Запись появится в Настройки →
   «Проверить» как неразобранная. Выберите «Это не операция».

Ответы скрипта при ошибке:

| Ответ | Причина |
|---|---|
| `"error":"unauthorized"` | неверный токен в поле `token` |
| `"error":"bad_request"` | пустой `text`, неизвестный `source` или тело не JSON |
| HTML-страница вместо JSON | неверный адрес или доступ к веб-приложению не «Все» |

## Что происходит дальше

1. Скрипт кладёт запись в лист `inbox` со статусом `new`. Повтор той же записи (тот же
   текст и то же `time`) не создаёт вторую строку.
2. Приложение при синхронизации забирает новые записи, сохраняет у себя и ставит им в
   таблице статус `fetched`.
3. Приложение разбирает каждую запись:
   - **Apple Pay** — по полям `payload`;
   - **уведомление и SMS** — по правилам из Настройки → «Правила разбора».
4. Если Apple Pay и уведомление банка описывают одну покупку (та же сумма и валюта,
   разница во времени до пяти минут, получатели не противоречат друг другу), создаётся
   одна операция с пометкой «Apple Pay + банк».
5. Категория подставляется по получателю, если вы уже выбирали её для него раньше.
6. Всё, что не удалось разобрать или у чего нет категории, попадает в «Проверить».
   Запись в таблице получает статус `done` или `needs_review`. Молча ничего не теряется.

Правила для уведомлений вашего банка описаны в [notification-samples.md](notification-samples.md).
