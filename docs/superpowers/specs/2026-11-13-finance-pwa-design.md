# Личный трекер финансов (PWA): дизайн

Дата: 2026-11-13. Статус: подход утверждён пользователем.

## Зачем

Один пользователь ведёт личные доходы и расходы на iPhone (iOS 27). Данные должны
оставаться у него: на устройстве и в его Google Таблице. Никаких подписок, платных
сервисов и Apple Developer аккаунта. Таблицу потом читает Claude через Google Drive.

## Цели

- PWA на русском, ставится на экран «Домой» из Safari, работает без сети.
- Источник правды: IndexedDB. Облачная копия: Google Таблица через Apps Script.
- Автотраты из Команд iOS (Apple Pay, уведомления банка, SMS) через лист inbox.
- Импорт xlsx/csv (профиль Money Manager), экспорт JSON и csv.

## Не цели

- Бюджеты и лимиты.
- Несколько пользователей, учётные записи, сервер.
- Шифрование на устройстве (только оставить место под него).

## Анти-цели (провал, даже если работает)

- Любой сторонний скрипт, CDN, аналитика, внешний шрифт.
- Токен или реальные данные в репозитории.
- Запись, потерянная молча (неразобранное идёт в «Проверить»).
- Данные, пропавшие при обновлении PWA.
- Придуманный формат уведомлений банка: парсер пишется только по образцам.

## Ограничения

- Статика на GitHub Pages, репозиторий публичный.
- CSP meta: `default-src 'self'`; `connect-src` только `https://script.google.com`
  и `https://script.googleusercontent.com`; без inline-скриптов.
- Запросы к Apps Script: POST, `Content-Type: text/plain`, JSON в теле, токен в теле.
- Начальные остатки счетов только локально (и в JSON-бэкапе).
- Тёмная тема, палитра и шрифт IBM Plex Sans по заданию; касания не меньше 44px.

## Подходы

1. **Без сборки: HTML, CSS, ES-модули (выбран).** Репозиторий и есть сайт. CSP и
   service worker простые, нечему ломаться, нет зависимостей в рантайме.
   Минус: шаблоны интерфейса пишутся руками через DOM.
2. Vite и лёгкий фреймворк (Preact, Svelte). Удобнее компоненты, но появляется
   сборка, деплой через Actions и зависимости, которые надо обновлять. Для одного
   пользователя и десятка экранов не окупается.
3. Нативное приложение. Исключено: нет Apple Developer аккаунта.

## Решения исполнителя (не согласованы отдельно, можно поправить)

- Тесты: встроенный `node --test`. Dev-зависимость `fake-indexeddb` только для
  тестов, в сайт не попадает. Логика (деньги, выборки, модель) отделена от DOM.
- Навигация по hash (`#/`, `#/add`), один `index.html`.
- Суммы: целое в минимальных единицах (тиын, ×100). Формат «107 700 ₸», копейки
  показываются, только если они не нулевые.
- `date`: локальное время строкой `ГГГГ-ММ-ДДTЧЧ:ММ:СС` без пояса; `updated_at`:
  миллисекунды UTC.
- Итоги на главной считаются в валюте по умолчанию (KZT). Операции в другой валюте
  видны в списке со своим знаком, но в итоги не входят. Конвертации нет.
- Все хранилища IndexedDB создаются сразу в схеме v1 (transactions, categories,
  accounts, templates, inbox, rules, settings), чтобы реже мигрировать.
- Графики: собственный SVG.
- `fingerprint` для ручных операций пуст; формула определяется в M3–M5.
- Место под шифрование: весь доступ к данным идёт через `js/db.js`, запись и чтение
  проходят через одну пару функций, куда позже встанет шифрование.

## Вехи

M1 каркас и ручной ввод. M2 аналитика, категории, счета, шаблоны, бэкап.
M3 Apps Script и синхронизация. M4 разбор автотрат по образцам. M5 импорт.
После каждой вехи остановка и показ результата. На каждую веху свой план в
`docs/superpowers/plans/`.
